# Split-merge moves, other literature, and which models can use what

Follow-up to `report_20261004_1731.md`, branch `ccr-79b8eb7e-96dy4t`. Questions: is there other
literature (optimal transport, say) that gives better MCMC moves; if not, add a SAMS-style split-merge;
and which models can use today's additions (unsupervised or semi-supervised, densities, missing data)?

## 1. Other literature

I checked the existence of the papers below by search; I read abstracts and summaries, not the full texts
(except where stated in `theory.md`, section 7).

* **Optimal-transport couplings for partitions** (Nguyen, Trippe and Broderick, AISTATS 2022, PMLR 151,
  3483-3514). Couples two chains on the *partition* space so that they meet quickly despite label
  switching; it builds on split-merge-type moves. Its use is *unbiased estimation and a certificate of
  convergence* (meeting times), not a better move. It is the route to the certificate that `theory.md`
  section 6 says is missing. **Not built**; it needs coupled versions of every update of the sweep.
* **Optimal transport for label switching** (Monteiller et al., NeurIPS 2019). Post-processing of draws
  into the quotient space. It does not change the sampler and does not help with multimodality over
  partitions (label permutations are not the modes in question).
* **Transport-map and neural-transport MCMC.** Move continuous parameters; the multimodality here is in
  discrete labels, so these do not apply to the problem.
* **Particle Gibbs split-merge** (Bouchard-Cote, Doucet and Roth, JMLR 18, 2017). Sequential Monte Carlo
  proposal inside a conditional-SMC kernel. Cost is `O(N |s|)` per move. A heavier alternative to the move
  added here; not built.

No optimal-transport method I know of replaces an exact partition-space move, so I added the split-merge
move. I did not search exhaustively; absence of a method in this list is not evidence that none exists.

## 2. What was added

`split_merge = m` in `callMDI`, `runMCMCChains`, `fitMDI`, `smcMDI`: `m` attempts per view and sweep of a
sequentially allocated reallocation between two random components, with an exact
Metropolis-Hastings ratio (`theory.md` section 5b). It follows the *style* of Dahl (2005); it has no
anchor items and is not his algorithm verbatim. Collapsed marginals (G, MVN, C) are implemented for the
tempered target; component parameters are redrawn after an accepted move.

**Guarantee (finite state space, Lean):** MH with a positive proposal is invariant; the sequential ratio is
`prod Z(proposed) / prod Z(current)`. Invariance of the whole move follows by conditioning on the pair,
the order and the items outside the pair.
**Not guaranteed:** mixing or any speed-up.

## 3. Checks and what they show

| Check | Result |
|---|---|
| Exact rational kernel (3 data sets, all visiting orders) | detailed balance, invariance, normalised proposal exact; mutant caught |
| Collapsed marginals vs quadrature / closed form | agree to 1e-8 (G, C) and 1e-9 to 1e-14 (MVN) |
| Move alone vs exact enumeration (C, G, MVN, `beta` 0.5, observed labels) | TV at chain-noise level in all six cases; control TV 0.64 |
| Full sampler, `split_merge = 2`, plain / tempered / PT | consistent with exact; one cell mean z^2 1.45 (expected 1.12, about 1.8 sd); controls rejected |
| Semi-supervised (2 observed labels), plain / PT / split-merge / `beta = 0.4` | consistent with exact; control rejected |
| Two views (MDI coupling), split-merge on, plain / `beta = 0.5` / PT | consistent with exact (MC prior reference); control TV 0.22 |
| Missing data | agrees with the plain chain (max abs z 2.34, mean z^2 1.17, 28 pairs); no exact reference |
| Mutant (always accept) | caught by two of three exact cases in `test-splitmerge.R`; the `beta = 0.5` case did not flag it |
| Four-cluster example, pooled plain chains | TV to reference 0.31 (without) to 0.015 (with split-merge); 0.001 at separation 4 |

On the 0.015: at separation 2.5 a 0.015 gap on one pattern persisted with 5 times longer chains and
standard error 0.001. The reference treats each true group as one unit and ignores item-level
misallocation. At separation 4 the gap vanishes. I attribute the gap to the reference. This is an
inference, not a proof.

## 4. Which models can use what

"Verified" means checked against an exact reference for a small case in this work. "Runs" means executed
without error here, with no exactness check. Entries are for views of type G (1-d Gaussian), MVN, C
(categorical); the same rows apply to each view of a multi-view fit.

| | split-merge | parallel tempering (`betas`) | SMC / AIS (`smcMDI`) | weighted helpers |
|---|---|---|---|---|
| G, MVN, C; unsupervised | verified (C, G, MVN) | verified (C, G) | unbiasedness verified (C) | yes (need SMC output) |
| G, MVN, C; semi-supervised (observed labels) | verified (C, MVN) | verified (C) | **refused** (explicit error) | no |
| missing values (data augmentation) | runs; sampler agreement only | **refused** | **refused** | no |
| TAGM (outlier component, complete data) | verified (exact joint law of label and flag, move alone); full sampler agrees with plain chain | **refused** | **refused** | no |
| TAGM with missing values | **refused** | **refused** | **refused** | no |
| GP (Gaussian process) | **refused** | **refused** | **refused** | no |
| several views (MDI coupling) | verified (2 views, N = 4, K = 2, MC prior reference; plain, `beta = 0.5`, PT) | verified (2 views) | runs | yes |
| tempered target (`beta < 1`) | verified (C, MVN move; C in full sampler) | by construction | by construction | |

Two cautions. First, "verified" refers to tiny problems (seven or eight items), where exact enumeration is
possible; larger data sets rely on the argument and on the small-case agreement. Second, semi-supervised
SMC is refused because exact prior draws are unavailable given observed labels; semi-supervised users get
tempering and split-merge but not weighted ensembles with the unbiasedness guarantee.

## 4b. Addendum: TAGM

Added after the first version of this report (the earlier refusal was a scope decision, not a mathematical limit: the
outlier density is fixed per item). Each item chooses a (component, outlier flag) pair; see `theory.md` section 5b.
Exact enumeration over (label, flag), N = 5, K = 3: TV at noise level for `eps` 0.1 and 0.4 and with observed labels; wrong-`eps`
control TV 0.77; a mutant that ignores the current flags in the reverse walk is caught (TV 0.12). Full sampler: agreement with the plain
chain for a TAGM view alone and coupled to an MVN view; no exact reference at that level. Outlier plus missing values stays refused.
Tempering and SMC still refuse outlier components, because the outlier density is not tempered in the allocation draw.

## 5. Limits

* No mixing guarantee for split-merge or tempering; no certificate built.
* The group-unit reference limits the precision of the four-cluster comparison at separation 2.5.
* The two-view check has K = 2 and N = 4, so the random choice of component pair is trivial there and the coupling
  factors act on very few items; the three-component pair choice is checked only for one view. One cell had mean z^2 1.37
  against 1.12 expected for 76 states (about 1.5 sd); the other three were 0.77 to 1.12.
